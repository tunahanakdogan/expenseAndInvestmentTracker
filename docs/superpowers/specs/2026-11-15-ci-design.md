# CI (GitHub Actions) — kısa tasarım

## Amaç
Her PR'da backend ve frontend testleri otomatik çalışsın; ruleset'te zorunlu kontrol yapılınca testi kırık kod `main`'e giremesin ("geçmeyen testle bitti deme" kuralının otomatik hali).

## Kapsam
- Var: test + frontend prod build.
- Yok: deploy, coverage raporu, güvenlik taraması (sonra eklenebilir).

## Yaklaşımlar
- **Tek workflow, iki paralel job (`backend`, `frontend`), filtre yok — seçilen.** Basit; zorunlu kontroller her PR'da raporlanır.
- Klasöre göre path filtreli workflow'lar — reddedildi: zorunlu kontrol, dokunulmayan klasörde hiç raporlanmaz ve PR "bekleniyor"da kilitlenir.
- Backend/frontend için ayrı dosyalar — reddedildi: aynı sonucu daha çok tekrarla verir.

## Tasarım
- Dosya: `.github/workflows/ci.yml`.
- Tetikleyici: `pull_request` ve `main`'e `push`. `concurrency` ile aynı ref'te eski çalışma iptal edilir.
- `backend` job: ubuntu-latest, Temurin JDK 25 (Maven cache), `./mvnw -B test` (`backend/` içinde). Testcontainers runner'ın Docker'ını kullanır; secret gerekmez.
- `frontend` job: ubuntu-latest, Node 26 (npm cache, `frontend/package-lock.json`), `npm ci`, `npm test -- --watch=false`, `npm run build`.
- Job adları sabit: `backend`, `frontend` — ruleset'te bu adlar seçilecek.

## Uygulayıcıya kalanlar (Claude'un kararları)
- Action sürümleri (checkout, setup-java, setup-node) güncel ana sürümlere sabitlenir.
- `permissions: contents: read` (en az yetki).
- İlk yeşil çalışmadan sonra kullanıcı ruleset'e "Require status checks to pass" + iki kontrolü ekler.
